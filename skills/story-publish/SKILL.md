# 发布平台书籍资料

## 目标与边界

帮助作者填写发布平台建书表单中的题目、简介、作者/笔名、主角名、标签等资料。若作者已经确定书名、简介、作者，保留原值并完成缺项核对；不要擅自重写。大纲、细纲、正文可支持生成候选值，但不能替代作者对平台字段的确认。平台字段和值以对应平台的参考文件为准，作品事实以作者明确提供或确认的材料为准。剧情规划、卷纲、细纲和正文写作属于 `story-long-write` 等写作 skill；仅说“帮我开书”且交付物不明时，先区分要规划故事还是填写平台建书资料。

作者约束：生成书名中的符号须为中文符号（如 `：，！？（）《》`），总长最多 15 个字符。每个汉字、数字、符号均计 1；英文字母、内部空格如有也计数，`……`、`——` 各计 2。列出候选前逐个预检并注明字符数。作者已定书名不合规时指出问题并给建议，不擅自改名，确认前不作为可填写定稿或封面定稿。

## 复用写作工程

先用作者指定的书目录；未指定时，可根据当前工作区的 `.active-book` 找到本书。指向不明或多本书无法区分时，询问作者，不从目录名猜定要发布哪本。只读取已有产物，不启动写作阶段或修改设定。

- 长篇：优先读 `设定/题材定位.md` 的基本信息、作者已定和核心设定；主角需要核对时读 `设定/角色/` 中相关角色卡；简介需要剧情支撑时按需读 `大纲/大纲.md`、卷纲和相关细纲。
- 短篇：读本书的 `设定.md` 与 `小节大纲.md`。其中的投稿导语属于正文开头，不直接当作平台“作品简介”。
- `选题决策.md`、拆文或扫榜材料只能支持作者要求的定位、书名或简介建议；它们不是本书的已确认事实，更不是平台候选标签清单。

证据优先级：作者本轮明确指定的字段值、作品文件中“作者已定”的决定、其他设定与大纲、市场或对标材料。后两层只生成待确认建议；暂定书名、角色卡姓名不自动变成最终书名或“主角1/2”。

## 复用封面能力

书名和作品简介均已确认后，主动进入封面准备，先检测 `story-cover` 入口与当前会话实际可调用的生图工具；不能仅凭模型名称判断支持生图。有能力时请作者确认“直接生成封面”或“仅生成提示词”，也可暂缓；无能力时说明限制，请作者确认“仅生成提示词，供外部绘图使用”或暂缓。作者已明确选择且当前仍可执行的模式不重复询问；未确认模式时记录待选择，不调用生成流程。API 仅在作者明确指定且环境就绪时作为可用通路，不因工具缺失自动改用付费接口。

把已确认的书名、简介、笔名、平台、题材及角色/场景事实传给 `story-cover`，缺笔名时补问。选择生图时走其原有生成、保存和质量检查流程；无生图能力或作者选择仅提示词时，走其 Step 1-3 的仅提示词模式。两种模式都把完整提示词原文写进“封面”，不只给提示词文件路径；生图成功后另记实际图片路径。提示词标为“建议/待作者确认”或“作者已确认”，与图片是否生成分开记录。暂缓、调用失败或入口不可用时写明待办和原因；生图失败后需作者同意才切换仅提示词。

OpenClaw 可能受 Key/命令发现门槛限制，不能因提示词不调用 API 就假设入口可用。缺项不阻塞其他资料，不把提示词或未保存的图片称为“封面已备妥”。
`story-cover` 给出的风格或尺寸建议不能替代本平台适配资料中的表单规则；资料没有确认的封面规格，仍标记“待平台核实”。

当前支持：番茄小说。先读 `references/fanqie-2026-10-08.md`，再读 `references/fanqie-stages-2026-10-28.md` 确认账号、作品类型和阶段；标签文件按需读。标签核验日为 2026-10-25，阶段报告补充日为 2026-10-28，原版本 2026-10-08 不是平台更新时间。报告中用户实测转述、公开规则及第三方参考不得混为独立后台验证。其他平台没有适配，不套用番茄规则。

## 工作流程

1. 确认用户打算发布到哪个平台。若未说明，先问平台；可同时根据已有作品材料制作平台无关的题目或简介草案，但不得把它称为平台可用标签或可提交资料。若平台未适配，明确说出平台名称和“当前未适配”，索取该平台带版本更新时间的当前表单、截图或官方说明；在取得资料前仅提供平台无关草案。
2. 在回复开头告知目标平台、适配状态、适配资料的实际核验日期和适用条件；平台官方更新日期有证据才写。番茄标签注明“原资料版本 2026-10-08；男/女频 Web 创建作品标签 2026-10-25 核验”，不能把原版本称为平台更新时间，也不能把该入口的候选范围推广到其他阶段。未适配平台写“核验日期：暂无”。
3. 判断任务是整理已有定稿，还是生成候选。已有书名、简介、作者/笔名和主角名时，先记录原值，仅核对用户要求的部分；依据大纲或细纲生成时，先抽取明示的作品事实，再为用户要求的字段提出候选。没有依据的字段保持待确认。作者/笔名可以列入书籍资料，但番茄参考文件未列出这个开书字段，不能宣称平台要求填写。
4. 先读取对应平台 Markdown 索引的元信息，确认版本和字段；只读取当前目标读者的阅读标签文件，以及任务需要的内容标签文件。逐字段核对允许值、选择上限和文本长度。参考文件未说明的限制，标记“资料未说明”。用户提供的实时表单与参考文件冲突时，指出差异并以当前界面为填写依据；保留差异记录。
5. 为每个字段标记来源和状态：`已确认`（作者明确指定为该字段的值或明确接受）、`建议`（由作品材料推导或新写的候选稿）、`待确认`（缺失、含糊、矛盾）、`待平台核实`（平台规则不明或已变化）。只把 `已确认` 内容放入“可填写值”。用户确认整个候选方案，也算确认其中明确列出的每一项；不要把沉默当成确认。用户仅提供故事简介、大纲或正文时，将其视为作品素材，不能自动当作已经确认的“作品简介”字段。
6. 先确认长篇或短故事，以及最小建书、补资料或提交发布阶段。补充报告将长篇最小建书必填项确认为书本名称、签约模式；“更新模式”不再作为独立必填字段。此结论不推广到长篇补资料、章节提交或短故事草稿；短故事发布按阶段报告单列必填项和未知边界。账号等级、实名及额度未知时列待核实，不阻塞资料整理。签约字数不是建书门槛。
7. 仅校验已填写或作者要求生成的字段。男/女频 Web 创建作品的阅读标签和内容标签均有 2026-10-25 后台截图逐项核验；其他入口与账号条件未核验。主分类在官方标签说明和两频弹窗中必选，但不推定全部建书/提交阶段都必填。数量、长度按有出处的口径预检；不要凑满上限。
8. 书名和简介确认后按「复用封面能力」确认模式并交接，保留完整提示词、封面状态和实际图片路径，再输出书籍资料、来源和待核实项。资料齐备时仅标记“发布资料准备完成”；尚未操作平台，不得写“平台已接受提交”“审核中”或“已公开发布”。本 skill 不负责实际填表、保存后台草稿或发布。
9. 当本轮资料需求完整、已确认值与留空决定均清楚时，按「回复格式」重排并落盘，再执行格式检查；不能沿用旧文件的标题和来源靠前的结构。长篇写在 `正文/` 上一级，短篇写在 `正文.md` 所在目录。平台待核实项可保留，不伪装成提交就绪；需求尚未完整时只展示草案。尚无正文也以已确定的书目录为准，不为定位而创建正文。

落盘文件命名为 `发布资料-<平台>.md`（如 `发布资料-番茄小说.md`）。写明目标平台、准备状态、原资料版本、实际核验日期、适用条件、各规则来源、已确认字段和待核实项；建议草案不冒充定稿。已有同名文件先读取；冲突时请作者确认，不覆盖手工修改。回复给出文件路径。

## 番茄小说适配

按 `references/fanqie-2026-10-08.md` 及其索引的分支文件执行，不凭记忆改写候选标签。原资料的“连载模式、完本模式”属于签约模式，不等于连载状态或更新安排；2026-10-12 官方调整对新建作品有作者等级限制，见索引。当前界面字段名称不明时先核实，不把签约模式值填进“更新模式”。

- 签约模式由作者结合账号资格确认，不从更新节奏推断；目标读者不从主角性别或文风推断。未确定时不选阅读标签；短故事不得复用长篇候选清单。
- 作者决定填写阅读标签时，先确定目标读者，再读取该分支的主分类、主题、角色、情节候选表。男频 Web 创建作品弹窗显示主分类必选且只能选一个，主题、角色、情节各最多两个；是否可在当前建书阶段不填整组，须以表单提交校验为准。相同文字出现在不同字段时，仍按字段分别核对。
- 内容标签按原文的情节、情感、人设、世界观四栏核对，上限依次为四、二、四、一。参考资料没有写各栏的最低选择数，也没有说明是否因目标读者而变化；不要自定最低数，遇到界面差异时核实。
- 主角 1、主角 2 的名字如填写，最多 5 个字；作品简介如填写，为 50 至 500 字。书名按上述作者约束预检；封面规格、平台书名上限及字符计数口径仍以当前界面核实，不把作者约束称为官方规则。
- 作者要求代拟封面方案、书名、简介或标签时，先读作品材料；输出为“建议草案”，写明依据和需要作者确认的字段。没有故事事实时，先问，不编造人物、情节、世界观或卖点。封面若只有需求而没有图片，不能写成“封面已备妥”。

## 回复格式

回复与落盘文件使用相同顺序。开头用 Markdown 引用块（每行 `> `）集中写元信息：目标平台、适配状态、准备状态、原资料版本、实际核验日期和适用条件。元信息后的第一个正文行必须是 `# 书本名称：<书名>`；不在它前面插入资料总标题、来源说明或其他小节。按下列顺序展开，基础字段按当前平台增减：

```markdown
# 书本名称：<已确认书名；未确认时写“待作者确认”>

- 作者/笔名：
- 签约模式：
- 目标读者：
- 主角1：
- 主角2：

## 封面

- 模式：<直接生图/仅提示词/暂缓/待作者确认>
- 状态：<提示词状态与图片状态分别说明>
- 提示词：<完整提示词原文；尚未生成时写原因>
- 图片：<已保存图片路径；未生成时明确说明>

## 阅读标签

- 主分类：
- 主题：
- 角色：
- 情节：

## 内容标签

- 情节：
- 情感：
- 人设：
- 世界观：

## 作品简介

<已确认简介全文>

## 待作者按照发布界面核实的内容

## 待平台核实

## 来源说明
```

标签各子字段必须独立成行，不用分号连成一段；同一子字段中的多个值可用顿号分隔。书名、简介、标签等平台填写值只放已确认内容，未确认留空；简介未确认时写“待作者确认”。封面提示词可附状态保留建议稿。候选书名、简介或标签集中放在“待作者按照发布界面核实的内容”中，标为“建议草案/待作者确认”，与需要作者检查当前页面的事项分开列。规则缺失或适用范围未知的事项放在“待平台核实”。后两节没有事项时写“无”；来源链接与核验依据统一放在最后的“来源说明”。不列完整候选清单，除非作者要求。更新已有文件时依此重排，保留作者手工内容。

封面小节必须在阅读标签之前。长提示词可用代码块保留原文，多方案用普通文字或列表编号；封面文件路径不表示已上传或发布。

落盘后用可用的 Python 解释器（依次探测 `python3`、`python`、`py`）运行 `scripts/check-publish-format.py <发布资料文件>`；脚本路径相对本 skill 根目录。检查只读，失败时修正排版并重跑，通过后再报告完成。无执行能力时重新读取落盘文件，逐项核对首标题、七个二级标题顺序、封面提示词和两组标签分行，并说明未运行自动检查。

## 扩展平台

新增平台前，要求资料明确给出版本更新时间，至少精确到日期；若有时分和时区，原样记录。缺少版本时间时不能宣称已适配，应向作者索取。把资料整理为 `references/` 下带 YAML 元信息的 Markdown 索引和按需读取的选项文件，不以 `.txt` 存储适配资料；在“当前支持”中增加索引入口，并补充该平台的字段、枚举、上下限和未知项。平台间字段名相似也不共享候选值；每个平台独立校验。没有材料的字段继续保持未知，不从番茄资料复制。
