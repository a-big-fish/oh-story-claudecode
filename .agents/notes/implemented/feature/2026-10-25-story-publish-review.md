# Agent Note: 番茄发布准备的证据与宿主接入

Status: implemented

## Problem

现有 `story-publish-details` 把用户提供的 2026-10-08 版本标记和后台实际核验混在一起，且把某个建书入口的必填条件推广到整个发布流程。新 skill 的 OpenCode、Antigravity 和真实 CLI 验收接入不完整；ClawHub 排除发行时主路由仍无条件调用。

## Decision

- 统一名称为 `story-publish`，当前只做番茄发布资料准备；资料产物区分已确认值、来源、待核实项和平台提交状态。
- 按建书、补资料、提交发布拆分规则适用阶段；2026-10-25 的裁剪截图逐项核验男/女频 Web 创建作品页的 691 个标签候选，其他入口、账号条件与提交校验仍不得宣称已核验。
- 补齐各宿主命令、部署白名单与验收清单；保留旧 13 个插件身份迁移夹具，当前 bundle 验收 14 个 skill。
- ClawHub 暂不发行新 skill 时，主路由在缺失时明确降级；逐包更新受影响版本与摘要锁，预算覆盖男/女频、内容标签、封面提示词叠加。

## Alternatives considered

- 立即把新 skill 纳入 ClawHub 发行：可消除缺装问题，但发行身份和授权证据未确认，不能替维护者做此声明。
- 把 691 个候选标签称作所有入口的官方清单：当前截图只覆盖特定账号的 Web 创建作品页，不能证明 App、其他账号或后续阶段的可选范围。

## Consequences

收益：发布资料可追溯，当前 Web 标签有去标识化截图证据，宿主发现和资料落盘流程一致。代价：其他后台阶段仍须作者在当前界面核验；ClawHub 单独安装 story 时不能自动提供新 skill。
